# 描画・性能契約

空間把握のための視覚優先順位は、湖面optic flow、地平線・対岸稜線とcockpit/wing/noseの自己基準、近距離固定物、中距離landmark、haze、装飾的なcloud・terrain textureとする。ゲームループ成立後は湖面を最初に実装し、以後も見栄えより速度・姿勢・高度・進行方向・scaleを復元する手掛かりを優先する。
WebGL描画はRenderSnapshotを入力とし、physics stateを変更しない。
Three.js固有の実装はengine adapterへ集約する。共通契約とassetの正本は `render-boundary.md` に従う。
Desktop・WebXR・Phone VRのbackendと光学profileは [presentation契約](presentation.md) に従う。
二眼描画ではreflection、cloud billboard、HUD、post-processingの両眼整合を検証する。
全Scene・overlayのScreen/VR対応を高品質描画に先行して確立する。
簡易worldでもPilot視点、ゲーム進行、Result/Analysis/Replayを完成させてから景観品質を追求する。その後は水面反射・波面・表面模様を先行させ、地平線・対岸稜線、cockpit/wing/nose、近距離固定物、中距離landmark、hazeの順に追加する。湖面描画は簡易worldで独立して開発し、地形・空の完成を待たない。

## Screenの3D描画解像度

Flight SetupとPause Settingsで100%・75%・50%を選択する。既定は100%である。
候補・表示順・ラベル・Screen限定の操作受付は共有Rustの`ScreenRenderScale`とgame UIが所有する。
設定は各物理描画軸の倍率であり、50%では3Dの画素数がおよそ25%になる。UIの論理解像度、画角、入力座標、固定物理tick、飛行記録は維持する。
Webは元のdevice pixel ratioと選択倍率を分離し、Three.jsの公開`setPixelRatio`へ積を渡す。canvasのCSS寸法は維持する。
最小化・極小寸法で描画軸が0 pixelになる場合はGPU targetのresizeを保留し、正の描画領域へ復帰した際に適用する。
Nativeは整数の物理寸法に共有`physical_size`を適用する。非整数DPRのWebでは最終段でfloorするため、整数化後に倍率を掛けるNativeとの投影差は各軸1 pixel以下となる。
Phone VRは元の描画倍率を使用し、WebXRのcompositor解像度は変更しない。VR退出・開始失敗後は保持したScreen設定へ復帰する。
反射targetはScreenの有効3D寸法に追随し、既存の上限・下限を維持する。解像度の低下はGPU負荷を抑える選択肢であり、80 FPSの達成保証は含まない。

Autoは共有Rustの単一`ScreenRenderAutoController`が解像度100%・75%・50%、shadow map 2048・1024・512、水面High・Medium・Lowを段階調整する。縮退は解像度、shadow、水面の順に下限まで進め、回復は逆順とする。水面は保持した手動選択を上限とし、Auto中の選択変更では上限より低い実適用値を維持し、上限を超える場合だけ下げる。既存の窓・epoch・閾値・ACK・cooldownを共有し、第二の計測履歴は持たない。ユーザーのAuto/Manual選択、保持した手動の解像度・shadow・水面、実適用値を分離する。Auto解除と明示Manual選択では保持した三値へ戻す。要求とACKはepochを含めた三値すべてを照合する。極小viewportではACKを保留し、準備失敗は既存資源と原因を保持する。新資源のcommit後に旧資源のcleanupが失敗した場合は、新しい適用済み値と元の原因を保持する。
Webは`EXT_disjoint_timer_query_webgl2`で反射と主描画を含むGPU command spanを非同期計測する。Nativeもsource frame・source時刻・epochに対応したGPU spanだけを受理する。通常のManualではAuto計測用GPU queryを発行しない。計測非対応は原因付きで表示し、欠損を0 msとして補完しない。
初期の2秒窓は最初の有効GPU source時刻から開始する。Webは反射と主描画が成功したframeの後から採取し、中断・資源交換後も再準備する。Nativeは現在の3D・shadow phaseが参照するpipelineの準備状態を確認し、作成中の短い未完成frameをAuto標本へ含めない。未使用pipelineは待機条件へ含めない。準備状態の変化は既存epochで失効させ、Readyは有効窓から導出する。新たなbenchmark phaseや物理clockは追加しない。
初期計測の完了は、同じ描画contextで最初に受領率90%以上の成熟窓を評価し、要求した資源を実ACKした事実として保持する。現在窓のReady/Measuring/Applyingは継続適応を表し、この完了事実と区別する。scene pipelineの再準備は窓だけを失効させる。明示Manual、新しいAuto、外部contextの失効、未対応、適用・cleanup失敗では完了事実も失効する。Nativeの初期完了確認には実ACK後のepochに対応するpipeline Readyと500 ms以内の有効GPU sourceも要求する。
2秒窓の8 ms区間ごとの有効GPU sample最大値を代表値とし、そのp95を判断に用いる。12.5 ms超は最低8代表値・1秒のsource span・500 ms以内の鮮度で下降を許可する。9.5 ms未満の上昇は最低30代表値・1.8秒のspan・100 ms以内の鮮度・同時間域のsource frame受領率90%以上を必要とする。適用後3秒は次の変更を保留する。
このp95は選別したGPU spanの統計である。全frame時間、CPU時間、present待機、全raw sampleのp95と区別する。欠損は有効な高負荷の履歴を消去せず、coverage不足時は上昇を保留する。resize、backend切替、context復帰、環境・描画品質変更、中断、disjointで古い窓を失効する。計測履歴と時刻はUIの構造cache keyへ含めない。
shadow調整は既存のDirectionalLightの実map寸法だけを変更し、cascade数・投影範囲・bias・太陽条件は維持する。shadowだけの変更では解像度targetを再生成しない。水面変更は既存の品質別meshと波浪成分の交換を使用し、reflectionの最低寸法、detail/sky texture、物理・記録・100 Hz tickを保持する。両adapterは要求資源を準備してから三値をcommitする。内部交換はACKによる窓失効を用い、外部の天候・品質変更と区別する。UIは保持上限・要求中・実適用の水面品質を区別する。これはAutoに限る画質と負荷の調整であり、High維持の高速化や80 FPSの達成を意味しない。
Webのshadow mapはrenderer共有資源として、Phone VR/WebXRへの切替後も適用値を保持する。VR中はScreen Autoの測定と要求を停止し、Screen復帰時は既存epoch/readinessで再準備する。VR向けAutoとbackend別shadow所有者は今回追加しない。

## 湖面

湖底は表示せず、不透明水面を採用する。空の明るさを維持しながら、水面の最終色は参照写真の暗い青灰色へ調整する。
空・雲・山・湖岸・太陽のreflectionとFresnel効果を含める。
太陽は微小波面法線によるsun glitterとして表現する。現段階は青みのある晴れ間、見える半球の約5%を覆う疎な積雲、水平線付近の淡い霞を持つ静的な全天テクスチャを背景空と水面反射で共有する。積雲は水平な雲底、複数の丸い上部、青灰色の下面と明るい上面を描く。太陽方向と雲量は定義済み環境metadataに接続し、欠損時には太陽と雲を表示しない。水面にはworld-spaceの波面・反射・表面模様を用い、画面内の流れから対地移動と姿勢変化を読み取れる状態を受入条件に含める。水体色の暗化は空の反射に適用せず、反射成分の水平線側の色を背景空に合わせる。反射強度は参照画像に合わせて45%に抑えた試作値である。Fresnel係数は幾何法線を基準とし、可視の微小面の係数を限定的に混合する。反射方向は視線側を向く微小面の法線を用い、裏向きの面では幾何法線へ戻す。遠方の微小波反射を視線角で一律に消さないため、反射方向とFresnel混合の可視条件を分ける。この処理は可視微小面を積分した厳密な粗面BRDFや空と水面の輝度一致を表すものではない。
Lowでも低解像度environment reflectionを維持し、reflectionの更新頻度と解像度を調整する。
Webの機体・雲reflection layerにはshadow receiverを置かず、map生成後のこのpassだけshadow map更新を抑止する。初回はThree.jsのshadow sampler資源生成を維持する。renderer共有の自動更新・明示要求flagは例外時も復元し、直後の主画面で水面・venueのshadowを通常更新する。反射geometry・照明・解像度は保持する。

Flight SetupとPauseのSettingsからLow/Medium/Highを選択する。Screen・Phone VR・WebXRは同じ選択肢を表示する。適用済み画質と要求中の画質を分離し、rendererがmeshと波浪成分を交換した後に適用完了を確定する。AutoのRunning中の交換も同じ資源境界を使用し、手動UIの受付条件を偽装しない。準備に失敗した場合は適用済みresourcesを保持し、再選択できる。画質だけの変更ではdetail texture、空・機体反射、simulation timeを維持する。天候変更・Retry・表示backend切替でも保持選択を維持し、物理・Difficulty・FlightRecord・Personal Bestの条件を変更しない。reflection更新頻度の最適化と性能目標の受入はBPG-012へ保持する。波面のJacobian・自己交差検査と実GPUのLow/High比較は、品質交換の接続とは独立した検証である。
交換後の旧geometry解放に失敗した場合は、新しい画質を適用済みとして保持し、解放処理の診断を表示する。準備失敗と交換後cleanup失敗を区別し、実rendererとUIの適用済み画質を一致させる。

試作湖面は有限fetch向けのJONSWAP形状と方向分散を持つ離散波浪成分、位相固定、Gerstner水平変位、非正弦波形、有限長の局所起伏、共有全天テクスチャの反射で構成する。全画質で同じ18成分の基準スペクトルを生成し、Low/Medium/Highで6/10/18成分を幾何波として描く。低画質の成分は全周波数帯を代表し、画質を上げると帯域ごとの方向成分を追加する。中短波の起伏は局所テクスチャで補い、画質に応じて水面mesh密度も変える。合成scenarioのWeather 5段階は描画専用の風向・風速・細部振幅・模様seedへ対応させ、天候選択時に波況を更新する。Mild以降の向きはscenario風に概ね合わせ、風速には過去の吹送で残った起伏を表す仮定を加える。Calmにも既存波を残す。登録済み環境metadataのwave inputsを使用し、Calm/Mild/Challenging/NearLimitの600 m fetchは描画用の仮定として保持する。飛行・リプレイでは確定した天候から同じ波浪状態を作り、simulation timeのみで位相を進める。この描画入力は琵琶湖の実測状態や瞬間風から計算した波浪予報ではない。太陽と空のreflectionは同じ環境sky inputsへ接続する。地形reflectionの高度化は後続の描画品質で扱う。

Webの幾何波はadapter内部の共有GLSL projection kernelを使用する。水面meshは平行移動だけを許し、local XZから頂点間隔 $s=s_0+(14.4/N)\max(|x|,|z|)$ を導出する。中心の勾配は0、同率の軸では両側勾配の平均を用いる。波の振幅勾配はpacketとLOD visibilityの両方を含める。fragmentの補間済み頂点間隔は微小法線の表示配分に限定し、この解析勾配へ転用しない。
CPUはquality補償後の実Float32振幅・方向・波数を用い、実meshの頂点間隔域で各成分の水平変位の微分上界 $B_i$ を計算する。方向norm、二段noiseのphase/packet勾配、LOD transitionのstationary pointと端点を含み、全域で非表示の成分は0とする。空間一定のchoppinessは $q=\min(4.5,0.56/\sum_i B_i)$ にFloat32用の数値余裕を加え、quality・Weatherの交換時に波と同時更新する。packet、phase、鉛直波形とdetail textureの表現は維持する。実数演算の解析上は水平変位のLipschitz上界が1未満となり、水平写像の反転を抑制する。
CPU回帰は上界・LOD境界・Float32 upload値・実meshの三角形を検査する。CPU referenceによる法線と差分の一致はGLSL実行の証明を含まない。GPU検査は同じkernelとupload値のtransform feedback、および実indicesの独立検査として実施する。texture高さ・fragment微小法線の厳密微分、全GPUの浮動小数点形式証明、時間的alias、optic flowの全時間受入、80 FPS達成は別の検証条件である。
Web/Nativeの頂点波形は、visibilityと実計算した空間勾配の両channelがすべて厳密0の成分について、packet・位相・三角関数の評価を省略する。非減衰のslope energyは同じ成分順ですべて加算し、crestの正規化を保持する。波形・LOD境界・fragmentのfwidth/filter・品質は変更しない。

機体の不透明な被覆・骨格は太陽光のshadow mapへ投影し、変位した水面の直射光を遮る。透明フィルムは不透明な板状影を落とさない。機体の反射は水面を挟んだ鏡映視点から半解像度の透明render targetに描き、水面の波面法線でサンプリング位置を揺らす。Screen・Phone VR・WebXRで同じ描画経路を用いる。反射視点は両眼の中央を代表する近似であり、厳密な両眼視差、波面の局所反射幾何、太陽の有限角度による影の半影は未実装である。
水面meshは6 km四方とし、視点付近へ頂点を集中させる。局所頂点間隔で幾何波をfilterする。中短波には、有限範囲の山と周囲の谷を多数重ねた2種類の周期テクスチャを用い、同じ高さ場から頂点変位と画素法線を作る。さらに近層を異なる回転・縮尺で2回参照し、細かな法線成分を重ねる。頂点で表せない距離では高さを減衰させ、画素法線はmipmapで平均傾きと傾きの二次モーメントを集約する。頂点法線に含めた勾配を画素へ渡して差し引き、幾何形状と画素法線で同じ起伏を二重に数えない。画素内の4位置で法線を評価して平均する。遠景の霞は弱く適用し、波の明暗を一律に消さない。側方視点でmeshの端や過度に早い細部の消失が見えないようにする。全ての波の位相はworld-spaceで評価し、水面meshが機体へ追従しても波形を動かさない。meshの表示範囲と波浪生成に仮置きした600 m fetchは別の入力である。
局所起伏は各テクスチャ辺長の1/96を特徴尺度とし、波頂片を6割、周囲の谷を伴う丸い起伏を4割配置する。波頂片は進行方向より波頂方向へやや長く、緩い曲率を持たせる。波片数を面積に応じて増やし、前後の設定で局所起伏の被覆率を概ね保つ。波片の中心はテクセルより細かい位置に置き、近層の頂点変位は格子間隔が0.12～0.32 mの範囲で減衰させる。
遠層のテクスチャ辺長は288 mとする。特徴尺度3 mの局所波に、特徴尺度4.5 mの低振幅な有限波を少数重ね、遠景の投影画素でも波頂片が残る帯域を設ける。両帯域は現状同じ移流係数を共有する近似である。
回転させた高周波2層は移動方向も同じ角度で回転させる。4層の移動速度の比は[深水重力波の分散関係](https://uhslc.soest.hawaii.edu/ocn620/lectures/surface-gravity-waves-1.html)にある位相速度 $c \propto \sqrt{\lambda}$ に近づける。この移動は帯域ごとの平行移動による視覚上の近似であり、波列内の分散や水深の変化はまだ表現しない。
微小法線の強度は描画カメラの高度から独立させ、スタート画面と飛行画面で同じ高さ場と風況を使用する。近層の局所起伏の振幅を抑え、細かい二層の法線変化を強めて短い波頂を描く。この調整は描画専用とし、飛行物理を変更しない。
波頂の局所振幅には下限を設け、微小法線は水面全体へ連続的に適用する。波のない斑状領域を作る強度マスクは使用しない。

将来のシナリオ波浪パラメータはscenario生成時に固定し、位相のみsimulation timeで進める。
局所水面から風上へrayを飛ばしてfetchを推定する。
fetchは風向と湖岸形状で決まり、湖中央からの距離だけでは決定しない。
風速・fetchのみから実際の波浪状態が一意に決まるとは仮定せず、風の継続時間や観測との較正を記録する。

大波はGerstner waveを候補とする。単なる正弦波の高さ和は鉛直変位モデルであり、
Gerstner waveの水平変位を含まない。実装時に水平変位、法線、steepness上限、自己交差回避を定義する。
Low 4–6、Medium 8–12、High 12–24成分を暫定予算とする。
微小波はnormal map/procedural normal。白波は波高・steepness・風速に応じて限定する。
波頂の鋭さはGerstner水平変位と平均高さが0の三乗波形で表現し、水平写像のJacobianが正となる範囲に抑える。三乗波形は山を狭く、谷を広くする。波頂に沿う位相と振幅は2段の二次元値ノイズで変化させる。局所起伏は非周期的な配置と山・谷の短い形で長い筋を減らすが、64 mと288 mのテクスチャ反復は残る。白波は波頂の局所圧縮に限定し、現在の局所風速だけで既存の波群の砕波を判定しない。写真上の明るい波筋をすべて砕波とみなさない。写真だけで実際の波高・fetch・吹送履歴は同定できない。描画専用の振幅調整はflight physicsと着水判定を変更しない。根拠は[NVIDIA GPU GemsのGerstner波の説明](https://developer.nvidia.com/gpugems/gpugems/part-i-natural-effects/chapter-1-effective-water-simulation-physical-models)、[NOAAの風浪・砕波の説明](https://oceanservice.noaa.gov/education/tutorial_currents/03coastal1.html)、[米国気象局の風浪とうねりの区別](https://www.weather.gov/marine/faq)による。
岸から沖への水深増加は水深分布が入力された時点で分散関係・浅水変形・砕波の条件へ反映する。現行scenarioは水深分布を持たないため、画面内の位置から水深を推定しない。
水面の見た目と静水面の着水判定は初期版では分離する。

## 地形・会場

Webの3D会場表示は、検査済みRust environment projectionのsourceから純粋に導出する。Titleは明示的な会場展示、現行session・そのResult/Replay・独立Attractは共有launch venueの表示座標契約を使用する。Calm/Mildの地理原点未記録状態は保持し、会場展示によって地理原点が記録されたと扱わない。
imported archiveはfull scenario identityに対応する登録済み環境と、記録されたlocal NED原点・water-level datumが会場assetと一致する場合に限り地形・湖岸・島・発進台を表示する。未知identityまたは原点未記録のarchiveはこれらを非表示とし、水面・機体・記録再生は維持する。archive退出後のTitle展示と現行flightの会場表示を復帰させる。表示切替は既存frame境界で適用し、physicsや保存recordを変更しない。

## 空間手掛かりの層

遠景の対岸稜線をworld-fixedなhorizon/referenceとして保ち、Pilot視点のpitch・roll判読を支える。機体のnose・wing/cockpit横線はbody-fixedな自己基準とし、外界と同時に視認できる。
近景はplatform・buoy等の固定objectでoptic flowを生成し、中景は島・湖岸・識別可能なpeakでheading・横流れ・scaleを補う。近・中・遠景のparallaxを維持し、均一なskyboxやtextureだけで距離感を代替しない。
地形・物体・機体の描画は同一world scaleと姿勢変換を用いる。decorative detailより先に、pitch・roll・yaw・速度・高度の変化を読み取れることを受入条件とする。

松原会場は湖岸線、砂浜、platform、松林、観客エリア、仮設構造物を優先する。
彦根近傍は中精度、対岸・山地は稜線とpeakを保持するlow-poly geometryとする。
500 m移動でのparallaxを保持するため、全遠景をskybox画像へ置換しない。
screen-space errorと複数視点の稜線誤差で簡略化を検証する。
多景島とオコノ洲はOSMの島輪郭内でterrain patchを元格子の半分の間隔へ再サンプリングし、陸上に分類されたAW3D30 DSM標本から各点の高さを補間する。多景島の樹冠面もOSM輪郭で閉じ、深緑の色変化を加える。水域に分類されたDSM標本は再構成面にも使わない。植生高は加算せず、表示meshは飛行物理・collisionへ適用しない。

現行の彦根環境試作はOSM relation 63499の湖岸線・島輪郭、AW3D30の広域300 m格子、離陸地点を含む12.06 km四方の30 m湖岸・飛行圏格子、主要4島・対岸4峰の90 m/30 mパッチ、小島輪郭用の10 mサンプリング格子で構成する。30 m湖岸・飛行圏格子は外周1,800 mで広域面へブレンドする。湖岸付近は90 m格子が細い陸地を取りこぼすため、30 m格子を維持する。対岸4峰は90 mへ粗く集約して遠景頂点数を抑える。10 m格子は30 m AW3D30画素を再参照するため、実標高の解像度を高めるものではない。AW3D30の欠測値は、OSMで陸地に分類された格子点だけCopernicus DEM GLO-30 Publicで補い、水域の値は使わない。両DSMの重複標本から求めた+0.3 mの局所中央値補正は描画用の位置合わせである。湖岸線・島輪郭・砂浜・樹林・桟橋・岸壁・防波堤はODbLのOSM asset、標高はJAXA AW3D30およびCopernicus DEMの利用条件に従う。砂浜と樹林のOSM分類は地形頂点色へ反映し、DSM標高に樹木の高さを加算しない。桟橋・岸壁・防波堤の3D幅と高さは地図形状を見せるための表示近似で、測量値・collision・飛行物理には使わない。発進点3 km四方のOSM湖岸線と局所地物をAnalysis mapへ使い、実会場を基準とするcamera_pointsを定義する。視点はおおよその試作配置であり、実測値として扱わない。発進台と地形を飛行物理・collisionへ接続しない。遠景の平坦な水面は近景の波面meshの下へ置き、水平線まで水面を連続させる。2026-09-30にlocal 5198の1280×720画面でTitleとDemo Replayの飛行中視点を確認し、見える範囲の水面・湖岸・対岸地形の間に明瞭な背景抜けがないことを見た。狭い水路・島岸の近接確認、姿勢を変えた複数視点の稜線誤差、500 m parallax・植生高さを含む現地照合は未完了である。

AW3D30の海岸側nodataとOSM湖岸線の間には、湖面datumから有効な陸上DSM標高へつなぐshoreline transition meshを置く。`assets/biwa-land-mask.json`でOSM上の水域と陸地を分け、水域にある標高値は地形から除外する。AW3D30の欠測陸地点はCopernicus GLO-30で補う。さらに同一格子内の小さな欠損は最大4セル以内で補間し、水域の欠損は補わない。海岸DSMの欠損が広い場所では粗い地形格子の最大8セル分（最大2.4 km）まで陸上面を探索する。岸線の短い欠損区間は局所岸線法線に沿って遷移面を補間する。OSMの短いline fragmentで陸側metadataが局所的に反転し、指定側に有効地形がない場合は、明示的なland maskを使って反対側を探索する。最終リングの標高は実際に描画する地形三角形から再サンプルする。水域と重なる未接続部は水面下へ沈める。波の上下変位と斜め視点で背景が露出しないよう、岸線から沖側へ240 m、水面下8 mまで重なる帯を設け、沖側2列とも海底下へ配置する。陸側外端は岸線法線方向へ5 m潜り込み、地形面より15 cm低く置いて、独立した三角形分割の画素間の隙間を塞ぐ。水中部分は水面に隠れる。
AW3D30に有効な標高がなくtransition meshを生成できない沖の白石の4輪郭には、OSM輪郭と高島市公表の最高14 mを基にした低ポリ岩礁meshを別に置く。最高14 mは4岩全体の見た目スケールだけに使い、残る3岩の高さは輪郭面積から得た表示推定値である。このmeshは水面下へ延ばして描画上の隙間を防ぐ。実測地形、collision、飛行物理には使わない。

これらの地形・湖岸・島の表示生成は共有Rust `venue_terrain`へ移し、Web/WASMとNativeが同じ完成meshを使用する。登録40岸線・17島輪郭、疎な多景島/オコノ洲のDSM補間、多景島の既存canopy面、沖の白石4輪郭、砂浜/樹林の頂点色を含む。canopyは元のDSM標本、島地表は補間後のgridを使う。water maskは地表生成で適用し、元の標高参照を破壊しない。属性はNED位置/法線とlinear色として渡し、adapterで法線や標高を再計算しない。CPUでの移植同値性と接続検査は、Nativeの実描画・500 m parallax・相対高さ・実VRの受入とは区別する。

## 空・雲・haze

共有 `LakeSceneHaze` はsRGB色 `0x9aafb1`、visibility由来のnear/farを所有する。sky未記録時は14 km/80 kmを使用し、metadataを補完しない。地形はcamera view-depth、水面・cloudはradial距離を用い、いずれもsmoothstepで混合する。Native地形は公式MaterialExtension/PBR helperを使用し、Webの通常Screenに合わせてsRGBで混合した結果をlinearへ戻して出力する。Webの既存縮小render targetではworking-linearのfogを維持し、この色空間差をpixel一致と扱わない。Nativeの直接・縮小・offscreen出力は同じterrain式を使用する。地形を含まない既存mirror passへhazeを追加せず、水面のradial hazeを一度だけ適用する。

BPG-008のconsumerは、Rustが現在のphaseとfull scenario identityから公開したsky metadataを使用する。太陽方位は北を0°とする時計回り、太陽高度は水平を0°とする。背景と水面reflectionは同一の晴天panoramaを参照し、DirectionalLightとsun glitterも同じ太陽方向を使用する。visibilityはterrainと水面の共通haze範囲へ接続する。haze開始距離はvisibilityの0.175倍とする描画上の近似である。
共有Rustの`lake_sky`は既存のseed `0x4f5a2c91`、lobe、noise、上下面の陰影からRGBA atlasと最大24cluster・48triangleの単一mesh packetを生成する。cloud fractionをcluster数へ写像し上限で制限する表示近似であり、雲量の測定的再現は主張しない。既存の角度分布を`cloud_base_m`から有限距離へ投影する。cloud baseは固定水面からの高さmであり、描画NEDの水面down=0に対応する。下端とworld上方向を保持し、各eye・反射viewは水平billboard方向だけを変更する。cameraのrollやpitchで雲の上下を回転させない。WebとBevyは同じpacketを本画面layer 0と既存水面reflection layer 1へ投影する。panoramaへ雲を重ねず、雲の計算と配置は共有Rust一箇所で管理する。各passの追加drawは1件、atlasは最大1024×768、全画質で同じ配置を使用する。
recordのsky unavailable、未知の環境identity、未選択状態は欠損を維持する。この場合は方位に依存しないrender-only gradientと既定hazeを使用し、太陽照明・sun glitter・cloudを表示しない。現在の環境metadataへ補完しない。共有cloud availabilityは`Unrecorded`・`Clear`・`GroundLevelUnsupported`・`Elevated`を区別する。cloud fractionが正でcloud baseが0の条件はground cloud/fogを積雲で表せないため有限clusterを生成せず、記録された雲量と既存haze条件を保持する。架空の正高度は補わない。現行登録assetのskyはTypicalのcloud base 1500 m・fraction 0.25のみで、他presetはsky未記録である。いずれも風場・接触面・物理tickを変更しない。

全天テクスチャ、haze、world-anchoredな積雲のbillboard/impostor clusterを基本とする。
雲は明るい上面、暖色寄りの太陽側、青灰色の下面を持つ。
共有Rustは同じlobeから前半球法線のRG8 atlasを生成する。各viewは記録済みのNED太陽方向をworld-up billboardのright/up/front基底へ変換し、既存Webのambient色とsunlight色の間で陰影色を補間する。反射viewにも同じworld太陽方向を使う。法線atlasは非色データであり、色atlasのみsRGBとして扱う。環境条件の交換時に生成し、frameごとの再生成は行わない。法線atlasは最大1.5 MiB、色atlasと合計最大4.5 MiBであり、mesh・draw数を増やさない。
山の稜線は識別可能に保持し、山下部は距離に応じて淡くする。
雲を水面reflectionへ反映する。雲影はHigh以上の任意機能とする。
volumetric raymarchは初期版の対象外である。

## 試作機体の外観

機体は鳥人間大会の滑空機を想起させる架空の形状とする。主翼はNACA 4412に準じた翼型断面、テーパー、上反角と細い支持材を持つ。主翼前半は藍色の被覆、後縁側は薄い半透明フィルムと、その内側に見える水色のスタイロフォーム芯材、竹・バルサの薄茶色のリブと縁材で構成する。コックピットは写真を参考にした細い白いフレームを内部に持ち、前方を先細りの透明フィルム、後方を白い不透明なフェアリングで覆う。搭乗者モデルは表示しない。主要骨格は、翼幅方向にたわむ主翼桁と、その中央へT字に接続して尾部へ続く太い黒いカーボン管の2本で構成する。黒い構造材はこのT字のみとする。水平尾翼と垂直尾翼はそれぞれ全surfaceを取付角に従って回す。両尾翼も同じ藍色の前部、透明な後縁、水色の芯材、薄茶色のリブ・縁材で描く。ライブ飛行と記録再生のphysical tail incidenceを描画契約へ渡す。

主翼の上反角は半翼幅の約60%と80%で勾配が増す二段構成とし、翼面・桁・芯材・縁材で同じ高さを使う。上向きのたわみは、その上反角に重ね、一様分布荷重を受ける片持ち梁の近似式で描画する。試作値はヤング率45 GPa、桁断面二次モーメント4×10⁻⁶ m⁴、支持質量110 kg、基準対気速度9.5 m/sである。速度の二乗を荷重の視覚的な代理値とし、極端な変形を避けるため倍率を制限する。これらは実機の構造諸元や強度の推定ではなく、飛行力学、操縦応答、衝突判定を変更しない。
Webの主翼rod160本は、同じ共有Rust端点・半径から4群のInstancedMeshと1個の8角unit cylinderへ投影する。初期matrixを充填し、共有0.03 m/s閾値を超えた変形時だけFloat32 instance matrixとaggregate bounding sphereを更新する。既存材質・shadow・layerを保持し、instance bufferと共有geometryを解放する。集約後のculling粒度と実速度への影響は実GPUで検証する。

## 二系統尾翼の表示

`tail_incidence`の両尾翼はversion付きの公開架空geometryを使う。水平尾翼は面積2.5 m²、span 3.4 m、body quarter-chord `(-arm,y,0.1)` mの矩形surfaceである。公開モデル`bpg041-playable-hybrid-mock` / model version 3のarmは3.6 mとする。垂直尾翼は面積0.5 m²、span 0.7 m、body quarter-chord `(-1.8,0,z)` m、`z∈[-0.45,0.25]` mの矩形surfaceである。LEはquarter-chordからchordの1/4前方、TEは3/4後方に置く。水平尾翼と垂直尾翼は独立した親を持ち、全surfaceをquarter-chord軸まわりに回す。FRDから表示座標への変換後の回転は水平`+X`、垂直`−Y`である。

Webはliveのsealed snapshot identity、Result/Analysis/Replay/Attractは当該record contextのconfiguration IDとmodel versionからengine非依存の`TailPresentationGeometryAvailability`を導出する。未登録の組合せは`unavailable`として保持し、adapterは尾翼表示を拒否する。未知のidentityを既定モデルのgeometryへ置換しない。Bevyの既定機体表示は共有session準備と同じPlayableのcore `HybridMockDefinition`のsectionからanchorと矩形頂点を導出する。描画契約の寸法はengine adapterの投影だけへ使用し、physics state、record、係数、contact geometryを変更しない。

主翼・コックピット・構造材はrender-only外観として共有する。その寸法とたわみは力学geometryの根拠へ流用せず、実機CADの再現性を保証しない。

## 画質

Auto / Low / Medium / High / Ultra / Customを用意する計画である。
項目はresolution scale、terrain LOD、water、reflection、shadow、cloud、particles、post-processing。
Autoは起動時benchmarkと実行時frame-time percentileを用い、hysteresisとcooldownを設ける。
PCの80 FPS目標ではp95が12.5 msを超えた場合の低下、9.5 ms未満での上昇を初期候補値とし、計測後に確定する。PhoneとXRは各presentationのframe budgetを基準に閾値を定める。Autoは計画段階であり、この閾値による適応画質や性能目標の達成は未検証である。
適応画質は水面反射を無効化せず、速度・姿勢の判読に必要な波面と反射の最低品質を維持する。縮退時はresolution scale、shadow、cloud、terrain、particles、post-processing、水面の高周波detailの順を基準とする。反射解像度・更新頻度は最低品質を下回らない範囲で調整する。
手動画質とAutoを区別し、Customを無断で上書きしない。
WebとBevyのPC Screenは安定した80 FPS相当、12.5 ms/frameを目標とする。スマートフォンは60 FPS、XRはruntimeのrefresh rateに対応するframe budgetを使用する。
PCの性能受入ではOS/GPU、解像度、DPR、画質、refresh rate、VSync、計測区間を固定し、平均値とframe-time percentileを記録する。
60 HzのRAF/VSyncで測定した実表示FPSと、80 Hz以上での80 FPS受入を区別する。FPS表示は描画frameの頻度であり、100 Hzのphysics tickを計数しない。
Webは成功したrender callback、Bevyは実時間のUpdate周期を750 ms窓で集計する。後者はGPUのpresent完了を直接計測する値ではない。
起動直後と長時間中断後は測定待ちを表示する。静止画、単体試験、debug buildの結果だけで性能目標の達成を判定しない。
CPU/GPU/転送量のbudget、対象端末、継続時間はBPG-012で数値化する。
画質変更は物理tickと物理モデルへ影響しない。
